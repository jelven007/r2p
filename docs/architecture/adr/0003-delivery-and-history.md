# ADR-0003：源码交付、合并与两个历史版本

日期：2026-10-24；状态：按本次交付要求采用。
适用：FR-007/008、NFR-003/004/007。

## 背景

用户要求更新生产工程目录及需求、方案、开发、测试、运营、运维文档，推送到 `https://github.com/jelven007/r2p`，合并分支并保留两个最近历史版本。
SDK 已改名为 r2p，注册表和站点发行仍没有独立准入证据。
直接删除提交历史会损失来源和回退能力；`v*` 标签会触发原有发布流程。

## 决策

本期交付固定 Git revision 的源码，目标分支为 `main`。
在功能分支提交、推送和创建 PR，通过适用检查后普通合并，保留全部祖先。
两个推荐恢复点使用不可变 `history/*` 标签，分别对应已验证 SDK 迁移快照和之前的上游基线。
标签及 SHA 的唯一清单为[history.json](../../releases/history.json)，检查工具要求恰好两项且本地引用匹配。
当前合并版本由 Git main/PR 表示，不重复计入历史快照清单。

外部 crates.io/PyPI/Netlify 发布 job 要求独立仓库变量显式启用，默认关闭。
完整 CI 仍是兼容性证据来源；远端运行缺失、资源问题和代码失败分别报告，不能标为统一通过。
首次包身份迁移无法直接与不同名称的旧 crate 执行语义版本比较，CI 显式记录该范围差异；后续同名 r2p 变更恢复比较。

## 选项与取舍

| 选项 | 影响 | 结论 |
| --- | --- | --- |
| 截断历史只留两个提交 | 损失上游来源、合并与恢复证据，需要强推 | 不采用 |
| 两个不可变历史标签，保留祖先 | 固定恢复点可审计，工具和用户易检出 | 采用 |
| 本次同时注册表/站点发布 | 需要名称权属、平台矩阵、制品和恢复验收 | 本期未启用 |

## 验证与后果

检查主/独立 workspace、相关 Rust/Python 回归、格式、文档、工作流结构、两个快照检出和 SDK 快照构建。
远端核验 PR 合并 SHA、main 与本地一致、两个标签匹配清单。
目录和内核迁移范围较大，上游同步继续在单独分支处理。
两份历史快照名称兼容性不同，恢复上游基线须配套恢复消费者 PyO3 名称。
具体结果见[生产工程验证](../../testing/reports/production-baseline-validation.md)和[交付记录](../../releases/records/2026-10-24-production-baseline.md)。
