# ADR-0002：产品身份与发行边界

日期：2026-10-24。
状态：产品与 SDK 内核名称 `r2p` 已由用户确认并采用；远端注册表发行尚未执行。
适用：FR-007、NFR-003、NFR-004。

## 背景

Git 仓库为 `jelven007/p2r`，上游来源为 PyO3。产品品牌确认后，用户进一步要求将 SDK 内核标识迁移为 `r2p`。
仓库拥有源码不意味着拥有上游包名、站点和发行权限。

## 决策

产品名称统一为 `r2p`，用于项目介绍、需求、方案、工程文档和运营材料。
根 [product.toml](../../../product.toml) 是产品身份的唯一维护入口，记录名称、实现包和源码来源。
产品基于 PyO3 的 Rust/Python 互操作能力建设，版权、许可与上游历史继续按来源保留。

| 标识 | 当前取值 | 含义 |
| --- | --- | --- |
| 产品名称 | `r2p` | 本次确认的对外产品身份 |
| 源仓库 | `jelven007/p2r` | 已核验的源码获取地址，保留实际链接 |
| Rust 实现包 | `r2p`、`r2p-*` | 现有 SDK 的 crate/API 和精确版本依赖 |
| Python 运行时包 | `r2p-runtime` | 现有实验组件的技术包名 |
| 本地既有工作区 | `p2r/` | 当前磁盘路径；新克隆示例使用 `r2p/` |

名称变更已落实到 Rust crate、`#[r2p(...)]` 宏属性、生成代码、`R2P_*` 构建变量、cfg、Python 模块、内省符号、stub、目录、模板与 CI。
`Py<T>`、`Python`、`PyErr` 等 Python 语言 API 保留原名。
当前 Maturin 按固定 `pyo3-ffi` 包名探测绑定，因此示例使用私有 `tools/maturin-bridge` 适配器；SDK 核心不依赖它。
构建配置优先使用 `R2P_*`，并在环境读取边界兼容打包工具传入的 `PYO3_*`。
迁移规则见[内核命名空间迁移](../../development/kernel-namespace-migration.md)。

独立公开发行前必须选择发行方式并形成记录：

| 方式 | 适用情境 | 必需工作 |
| --- | --- | --- |
| 上游协作 | 修改最终进入 PyO3 | 遵循上游贡献、兼容和发行流程 |
| Git revision / 内部注册表消费 | 内部先验证 SDK 改动 | 固定 SHA、依赖及构建证据，定义内部版本和支持责任 |
| 独立注册表包 | 建立独立产品 | 确认名称/许可/权限，更新所有依赖/宏路径/元数据/模板/文档并完整回归 |

当前没有选择或完成独立公开发行。
上游包索引版本、网站状态和社区规模不作为 r2p 运营指标。

## 生产准入

确认发行主体、包名、版本、注册表、站点域名、OIDC/凭证授权、环境审批、支持责任及回退机制。
流程见[发布与回退](../../maintenance/release-and-rollback.md)。

代码里的既有发布工作流用于分析与后续配置；它们的存在不证明已满足准入。
上游发行参考保留原文，避免把历史操作当成本仓库当前指令。

## 后果

当前产品资料与 SDK 技术接口统一使用 `r2p`；这是 Rust 源码与 Python 模块命名的不兼容变更。
下一阶段落实版本、注册表权限和站点配置；源码版本声明不代表已发布制品。
