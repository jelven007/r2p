# 变更、验证、发行与事故记录模板

状态：复用模板。
每次复制为实际记录并填写；未执行项写“未执行”及原因，不保留模糊勾选。
测试记录保存到 `docs/testing/reports/`，源码/发行记录保存到 `docs/releases/records/`；事故演练记录保存到 `docs/runbooks/records/`，发生时建立目录。

## 1. 记录标识与范围

| 字段 | 填写内容 |
| --- | --- |
| 记录编号/类型 | 变更、测试、发行、事故或演练 |
| 日期/负责人/审阅者 | 实际人员、时间及时区 |
| 仓库/分支/源码 SHA | 是否包含未提交变更；PR/提交链接 |
| 需求与决策 | FR/NFR、G、ADR、Q 或关联缺陷 |
| 问题与目标行为 | 具体触发、原行为、期望结果 |
| 影响范围 | 组件、API/ABI、解释器/MSRV、features、平台、文档和消费方 |

## 2. 方案与变更

记录最终实现、关键边界、不变量、兼容影响和取舍。
目录变动给出原→新路径及 Cargo/Nox/CI/mdBook/打包联动；发行身份变动给出批准依据。

列出实际变更文件和必要迁移步骤。
关联需求追踪矩阵与 ADR，避免重复维护需求定义。

## 4. 发行与制品

适用于发行；非发行记录填写“不适用”：

| 字段 | 填写内容 |
| --- | --- |
| 已批准身份/目标 | 包、注册表、域名、权限环境、支持范围 |
| 版本与来源 | 版本、标签/SHA、依赖快照、许可证 |
| 制品清单 | 名称、文件、目标平台/ABI、SHA-256、构建日志 |
| 核验 | 隔离安装/导入、重新下载哈希、文档/消费方结果 |
| 决策 | G1–G6 证据、批准/暂停、批准人、时间 |
| 支持与恢复 | 负责人、渠道、旧版本/哈希、演练记录 |
| 源码交付 | 目标仓库、PR、主分支 merge SHA、两个 history 标签核验；非源码交付填不适用 |
