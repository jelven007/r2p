## 3. 风险登记

| 编号 | 风险、触发和影响 | 处置 | 责任角色 |
| --- | --- | --- | --- |
| R-01 | 目录调整遗漏 Cargo/Nox/CI/mdBook 路径，导致构建或打包失败 | 迁移映射、自动路径检查、源文件保全和相关运行验证 | 开发负责人 |
| R-02 | 最新 Rust 与上游 UI 快照诊断不同，严格门禁失败 | 记录差异，核对工具链；不无审核批量改快照 | 测试负责人 |
| R-03 | 本机嵌入 Python 缺少可链接库，造成环境性测试失败 | 使用可链接解释器并固定环境，保留初始失败与后续结果 | 构建负责人 |
| R-04 | 将上游包名/站点/权限当作本仓库资源，错误发行 | ADR-0002、身份/权限核验、审阅触发器与目标 | 发行负责人 |
| R-05 | GIL/free-threaded/ABI 或实验特性被同一结论覆盖 | 矩阵分组、状态标识和真实运行证据 | 技术/测试负责人 |
| R-06 | 上游同步与新目录冲突，破坏本地工程基线 | 单独同步分支、迁移映射、冲突审阅与重新验证 | 技术负责人 |
| R-07 | stable 锁解析的新依赖超出 MSRV | 根锁已跟踪；MSRV 在隔离副本按 Nox 解析，发行保存实际快照 | 构建负责人 |
| R-08 | 拟定响应/性能/SLO 被误读为现有承诺 | 明确状态、批准人与生效版本，依据实际指标调整 | 产品/运营负责人 |
| R-09 | 新业务系统范围未定义，引入无依据的服务/数据库 | Q-01 单独立项，补充业务旅程、数据和部署需求 | 产品负责人 |

风险复核在范围、上游版本、解释器、工具链和发行目标变化时执行。
当前实际失败/限制与静态风险登记分别维护。
