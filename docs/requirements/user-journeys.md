# r2p 用户采用、开发与恢复旅程

版本：2.0；日期：2026-10-24；状态：当前 SDK 工程适用。
需求编号和验收门禁以[需求规格](system-requirements.md)为准。

| 旅程 | 输入与前提 | 主要步骤 | 可观察成功条件 | 失败处理 | 需求 |
| --- | --- | --- | --- | --- | --- |
| UJ-01 Python 原生扩展 | Python/OS/CPU 已选，Rust 工具链可用，固定 r2p SHA | 选择打包示例 → 声明模块/函数/类 → 构建 wheel → 隔离安装 → 参数/异常测试 | 模块可导入，正常与非法输入符合契约，wheel 标签匹配环境 | 按配置/链接/导入分类，收集最小复现 | FR-001/003/004/005/007 |
| UJ-02 Rust 嵌入 Python | 可链接 Python，初始化和进程退出策略明确 | 初始化 → attach → 调用对象 → 提取结果/异常 → 按生命周期释放 | 宿主运行、错误传播、对象生命周期回归通过 | 核对 libpython/架构；移除扩展构建模式 | FR-002/003，NFR-001 |
| UJ-03 SDK 维护 | 需求/缺陷编号，干净工作分支，影响范围明确 | 方案/ADR → 模块实现 → 相关回归 → 更新追踪和指南 → PR → 交付记录 | 同一修改包含代码、测试、兼容说明和可获取 SHA | 必需测试失败保持未通过，修复或缩小已声明范围 | FR-004/008，NFR-003/005/006 |
| UJ-04 类型 stub | 明确使用实验 inspect/async，二进制格式在已测范围内 | 构建元信息 → CLI 提取 → 比较 stub → Python 类型/行为检查 | 输出与模块一致，stripped/fat 行为有证据，协议错误可诊断 | 固定 SDK/内省版本并保留异常二进制样本 | FR-006 |
| UJ-05 PyO3 迁移/升级 | 原版本、依赖和关键消费场景已保存 | 包/导入/属性/配置迁移 → 固定新 SHA → 构建 → 消费方回归 | 模块行为保持期望，原版本可恢复，实验边界明确 | 依据迁移说明回到旧依赖和导入；不可混用内省协议 | FR-005/007，NFR-003/007 |
| UJ-06 故障和恢复 | 版本/SHA、环境、症状和影响 | 复现 PR → 定级/复现 → 固定已验证 SHA 或旧制品 → 验证 → 修复 PR/复盘 | 关键消费场景恢复，原因和回归关联同一记录 | 崩溃/ABI 问题暂停受影响交付，按故障手册升级 | NFR-007/008 |
