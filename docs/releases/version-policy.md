# r2p 版本、交付与历史保留政策

版本：2.0；日期：2026-10-24；状态：当前源码交付适用。
关联：FR-007、NFR-003、NFR-004、NFR-007。

## 1. 版本维度

| 维度 | 当前标识 | 用途 |
| --- | --- | --- |
| Rust SDK | `0.30.0`，主包和五组件精确对齐 | 源码/API 版本，尚未证明注册表存在该版本 |
| Python runtime | `0.0.1` | 独立实验包，版本不与 Rust SDK 自动联动 |
| 工程文档 | `2.0 / 2026-10-24` | 当前生产研发目录和流程基线 |
| 源码交付 | 主分支完整 Git SHA | 消费方固定实际代码和依赖解析 |
| 历史快照 | `history/*` | 两个可检出的恢复点，不触发 `v*` 外部发布 |

`PyO3 → r2p` 是包名、宏属性、Rust 导入、Python 辅助模块和内省协议的迁移。
原有 PyO3 版本说明仅是技术来源，不能据此声称 r2p 已对注册表消费者提供相同兼容承诺。
使用方按[内核迁移说明](../development/kernel-namespace-migration.md)迁移，并保存自己的 Cargo.lock。

## 2. 源码消费

从 [r2p 仓库](https://github.com/jelven007/r2p) 获取合并后的完整 SHA。
Cargo 依赖使用 `git = "https://github.com/jelven007/r2p"` 和 `rev = "<完整 SHA>"`，选择 `r2p` 包及需要的特性。
本仓库未确认 crates.io/PyPI 名称所有权；独立包发布后才能将示例切换为已发布版本。
Maturin 扩展还需要私有适配器，具体清单见[SDK 入门](../sdk/README.md)。

根 `Cargo.lock` 和 `uv.lock` 都已跟踪。
库消费者仍会解析自己的依赖，因此根锁文件验证不等于最低依赖/MSRV 验证。
MSRV 使用隔离副本运行 Nox 的兼容解析；更新工程锁文件必须说明 Rust 下限和测试结果。

## 3. 两个历史版本

[history.json](history.json) 是快照清单的唯一来源，按新到旧排列，必须恰好两项。
本次保留迁移后的 SDK 验证快照和工程迁移前的上游基线，完整提交祖先仍保留。
核验标签使用 `git rev-parse <tag>^{commit}`，并与清单完整 SHA 比较。
共享标签不可移动、强推或替换；后续新增恢复点使用新的名称。
清单轮换只代表当前推荐的两个恢复点，旧公共引用是否退役需单独评估，不能连带删除提交历史。

恢复操作在独立 worktree/克隆执行。
最新 SDK 快照保留 r2p 接口；上游快照需要恢复 PyO3 使用方式。
恢复主分支通过 revert PR，消费方固定最后已验证 SHA 后运行自己的回归。

## 4. 正式包发行

注册表发行遵循语义版本并协调六个 Rust 包、宏、构建配置、指南、模板和精确版本依赖。
增加 MSRV、降低解释器支持范围、修改 ABI/内省格式和不兼容 API 时提供迁移说明。
实验 async/inspect/no_std 另行标注，不借 stable 构建扩大支持范围。
外部发行满足[发行与回退](release-and-rollback.md)的 G1–G6 后才启用对应工作流变量和发布标签。

已公开版本及制品不可覆写。
问题版本采用平台支持的 yank/撤回并发布新修复版本，保存来源、哈希、影响和恢复记录。
