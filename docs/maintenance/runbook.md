# 运维操作与故障手册

日期：2026-10-24；状态：拟定运维流程；本地验证事实见[验证报告](../testing/validation-report.md)。
关联：FR-007、NFR-004、NFR-007。

## 1. 运维边界

SDK 没有常驻服务进程或业务数据库。
运维对象是构建/测试环境、注册表制品、文档站点以及消费方扩展的安装与运行问题。
消费方业务服务的流量、数据备份和容灾由其自身系统负责。

本仓库已有 GitHub Actions、Netlify 资源、uv/Nox、Rust 和 Python 打包工具；当前未验证本仓库远端权限、秘密配置或线上站点。
本手册不将既有上游 URL 视为本仓库部署目标。

## 2. 角色与资产

| 角色 | 职责 |
| --- | --- |
| 运维负责人/值班角色 | 故障接收、定级、止损、协调和时间线 |
| 构建负责人 | 工具链、缓存、依赖、平台和日志定位 |
| SDK 技术负责人 | 语义、ABI、引用、并发和崩溃分析 |
| 发行负责人 | 暂停/恢复发行、版本、制品、注册表与站点回退 |
| 测试负责人 | 最小复现、影响矩阵、回归和恢复验证 |
| 支持负责人 | 消费方影响收集、授权渠道反馈和问题闭环 |

G6 前建立资产台账：仓库/分支保护、Actions runner、注册表身份与授权、域名/站点、构建依赖、负责人、支持窗口和升级渠道。
权限使用平台环境/OIDC或受控凭证；轮换和撤销形成记录，不在日志中输出秘密。

## 3. 日常检查与信号

| 对象 | 信号与触发 | 响应 |
| --- | --- | --- |
| 必需 CI | stable/MSRV 或必需平台失败 | 阻断对应交付，区分源码、工具链、依赖和环境 |
| 打包制品 | 缺失、哈希变化、标签错误、隔离导入失败 | 停止分发，固定最后已验证版本 |
| 运行行为 | 崩溃、GC/借用错误、ABI 不匹配、并发退化 | 收集最小复现，启动严重故障处理 |
| 文档站点 | 目标页面不可访问、版本路由错误 | 核验已批准目标，恢复上一份已验证静态制品 |
| 依赖/工具链 | 更新后构建失败或诊断变化 | 固定已验证组合，评估升级差异 |
| 支持问题 | 同版本/平台重复导入失败或同根因复发 | 聚合影响，关联缺陷并提升优先级 |

SDK 可用性以对应制品可安装、导入和关键行为通过衡量。
站点、流水线的 SLI/SLO 和告警阈值需独立批准；不存在可直接沿用的 SDK 请求成功率或数据库 RPO。

## 4. 故障分级和处理

| 等级 | 判断标准 | 处理要求 |
| --- | --- | --- |
| SEV-1 | 已交付版本出现广泛崩溃、内存/数据完整性风险或关键消费方不可用 | 立即停止受影响发行，协调消费方固定旧版本，指定事故负责人 |
| SEV-2 | 特定受支持平台不可构建/导入，或关键功能明显回归 | 暂停该组合交付，给出已验证绕行/降级和修复计划 |
| SEV-3 | 非关键缺陷、教程失效、实验组合问题 | 分类进入正常缺陷与文档流程，明确支持边界 |

响应目标和通知人员由 Q-04 确认。
处置顺序：确认影响 → 保存证据 → 控制发行/消费范围 → 复现定位 → 修复或降级 → 验证恢复 → 复盘。
没有授权和身份确认时，不操作上游站点或注册表。

## 5. 排查操作

先收集以下只读信息；分享日志前移除本机个人路径、令牌和无关数据：

```bash
git status --short --branch
git rev-parse HEAD
rustc --version --verbose
cargo --version
python -c "import platform,sys,sysconfig; print(sys.version); print(platform.platform()); print(platform.machine()); print(sysconfig.get_config_var('Py_GIL_DISABLED'))"
cargo metadata --no-deps --format-version 1
python tools/check_repository.py
```

最后一条使用 Python 3.11+。
记录实际 `R2P_PYTHON`、ABI/features 和构建命令，不批量输出环境变量。

| 症状 | 排查步骤 | 恢复验证 |
| --- | --- | --- |
| Cargo 依赖/路径失败 | metadata、迁移映射、独立 workspace、生成模板 | 路径检查、受影响构建和包内容检查 |
| 找不到 Python 符号/libpython | 解释器架构、可链接库、扩展/嵌入模式和配置变量 | 同解释器嵌入测试或隔离 wheel 导入 |
| wheel 导入失败 | wheel 标签、导出模块名、动态依赖、目标 Python/ABI | 新环境安装并运行关键 API |
| UI 诊断不同 | Rust/rust-src、features、严格/ignore 模式、源文件位置 | 严格模式诊断通过；差异不得静默覆盖 |
| 崩溃/引用问题 | 最小输入、线程/GIL、生命周期、GC 和 FFI 不变量 | 复现不再失败，并覆盖相邻边界 |
| 性能异常 | 相同硬件、优化、解释器、特性、负载和重复样本 | 关联基准及消费方场景比较 |
| 站点路由失败 | SHA、静态制品、版本路径和重定向 | 已确认 URL/版本导航与页面抽查 |

## 6. 保全与恢复

保留源码 SHA、发行记录、依赖解析快照、工具链、日志、制品及校验和、站点静态制品与配置。
保存位置、访问权限和保留期由资产负责人确认。
SDK 无业务数据库备份任务。

恢复消费方时固定最后已验证版本/哈希，重新构建干净环境并运行关键业务回归。
恢复站点时重新部署保存的已验证静态制品和对应路由。
注册表处理是撤回/标记问题版本并发行新修复版本，不能假定可覆写已发布内容；详见[发布与回退](release-and-rollback.md)。

## 7. 复盘和演练

事故结束记录影响版本/平台、发现与恢复时间、根因、证据、恢复验证和预防任务。
预防动作关联需求、代码、测试、文档及负责人，不用“加强注意”替代可验证动作。

每个首次交付目标完成一次坏制品停止分发、固定旧版本安装和站点制品恢复演练；目标恢复时间在演练后按实际环境批准。
记录模板见[变更与发布记录](../governance/change-record-template.md)。
